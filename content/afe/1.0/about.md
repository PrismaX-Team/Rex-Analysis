# 这个 bench 测什么

在最优解尚未明确的科学前沿，衡量真正的创新能力。

Agent Frontier Exam 评测研究 Agent 能否面向真实、尚未解决的前沿科学问题，在开放的环境中自主调研，提出并验证改进方案，取得可衡量的进展，推进问题的边界。

# 设计哲学

一个能够持续向前的 Benchmark。

- **Live Question**：评测的不是解决办法明确的静态题目，而是仍未解决、并值得不断推进的真实前沿问题。
- **Live Environment**：在开放环境下，模型可以检索调研问题的前沿方法，公开前沿是研究的起点，而不是需要隔离的信息。
- **Live Metric**：评分规则固定，但比较坐标持续更新；每个结果都相对于其他 Agent 和当前前沿进行衡量。
- **Live Community**：Benchmark 不是一次性封闭发布的题库，而由研究者、领域专家等贡献者持续共同发现、构建和完善。
- **Innovation**：评测关注的不是完成既定步骤，而是 Agent 能否把调研转化为经过验证的改进，在尚未解决的科学问题上取得可衡量的进展。
- **确定性验证**：Verifier 在运行前冻结，并在离线环境中评分；相同的冻结输入、Validation 历史、Context 和提交必须得到相同结果。
- **受控评测**：资源和网络边界预先固定，研究过程被完整记录与审计，防止 hacking、访问隐藏输入或通过绕过约束获得虚假高分。

# 任务特性

- **科学重要性**：结果变好后，应能推进真实研究问题或重要科学计算瓶颈。
- **Verifier 可信度**：评分算法、输入、常数、容差、聚合和无效输出处理能够完整固定，并在本地、离线、确定性运行。
- **前沿空间**：当前最佳可达结果仍未知，并有可信证据表明存在实质改进空间。
- **长期可持续性**：数据、软件和验证路径能够稳定获得，不依赖脆弱服务、秘密凭证或不可重复的外部行为。

# 任务包

每个任务都是一份 Harbor 格式任务包，以 `task.toml` 为配置入口，`instruction.md` 为面向 Agent 的指令，解题环境与评测环境严格隔离。评测一次性对冻结后的提交离线、确定性地评分；最优可达结果事先未知。

```text
task_package/
├── task.toml                 运行配置与产物路径
├── instruction.md            Agent 可见任务指令
├── environment/
│   ├── Dockerfile            解题环境定义
│   ├── input/                Agent 可见输入
│   └── tools/                Agent 工具（按需）
├── tests/
│   ├── Dockerfile            独立评测环境定义
│   ├── test.sh               评测入口
│   ├── check_outputs.py      评分实现
│   ├── input/                独立评测输入副本
│   └── tools/                评测工具（按需）
├── harness/                  集成约定及外部调度适配材料（按需）
└── solution/                 参考解（私有，按需）
```

- `task.toml`：运行配置，包含任务名称、署名、资源限制、超时、网络模式与产物路径。
- `instruction.md`：面向 Agent 的完整任务说明，包含输入描述、输出格式、约束条件与成功标准。
- `environment/`：解题镜像构建上下文。`Dockerfile` 安装运行依赖；`input/` 存放 Agent 可见的科学输入；`tools/` 存放 Agent 可调用的工具代码与接口（按需）。
- `tests/`：独立评测镜像构建上下文，与解题环境严格隔离，Agent 修改解题输入不影响评分基准。评分结果写入 `/logs/verifier/reward.json`，详细记录写入 `metrics.json`。
- `harness/`：集成约定与外部调度适配材料，记录与 Harbor 或其他调度框架的集成方式（按需）。
- `solution/`：参考解，仅供 oracle 验证，不会复制到解题镜像（按需）。
