# 这个 bench 测什么

在最优解尚未明确的科学前沿，衡量真正的创新能力。

Agent Frontier Exam 评测研究 Agent 能否面向真实、尚未解决的前沿科学问题，在开放的环境中自主调研，提出并验证改进方案，取得可衡量的进展，推进问题的边界。

# 设计哲学

一个能够持续向前的 Benchmark。

- **Live Question**：评测的不是解决办法明确的静态题目，而是仍未解决、并值得不断推进的真实前沿问题。
- **Live Environment**：在开放环境下，模型可以检索调研问题的前沿方法，公开前沿是研究的起点，而不是需要隔离的信息。
- **Live Metric**：评分规则固定，但比较坐标持续更新；每个结果都相对于其他 Agent 和当前前沿进行衡量。
- **Live Community**：Benchmark 不是一次性封闭发布的题库，而由研究者、领域专家等贡献者持续共同发现、构建和完善。
- **Innovation**：评测关注的不是完成既定步骤，而是 Agent 能否把调研转化为经过验证的改进，在尚未解决的科学问题上取得可衡量的进展。
- **确定性验证**：Verifier 在运行前冻结，并在离线环境中评分；相同的冻结输入、Validation 历史、Context 和提交必须得到相同结果。
- **受控评测**：资源和网络边界预先固定，研究过程被完整记录与审计，防止 hacking、访问隐藏输入或通过绕过约束获得虚假高分。

# 任务特性

- **科学重要性**：结果变好后，应能推进真实研究问题或重要科学计算瓶颈。
- **Verifier 可信度**：评分算法、输入、常数、容差、聚合和无效输出处理能够完整固定，并在本地、离线、确定性运行。
- **前沿空间**：当前最佳可达结果仍未知，并有可信证据表明存在实质改进空间。
- **长期可持续性**：数据、软件和验证路径能够稳定获得，不依赖脆弱服务、秘密凭证或不可重复的外部行为。

# 任务包

每个任务都是一份五部分任务包：Instruction、Input、Environment、Verifier 与 Meta。Validation 在研究阶段按任务设定的预算向 Agent 提供反馈；Test 只对冻结后的提交离线、确定性地评分一次。最优可达结果事先未知。

- `instruction.json`：面向 Agent 的任务说明、输入声明、提交产物、已提供环境、额外要求与运行上限。
- `input/`：只包含 Agent 可见的科学输入与提交模板。
- `environment/`：`environment.json` 选择运营方默认镜像或任务专用 Containerfile。
- `verifier/validation/`：Agent 在研究过程中可请求的反馈；可没有。
- `verifier/test/`：提交冻结后的一次最终评分；离线、确定性。
- `meta.json`：任务身份、数据来源、指标语义与公开分数映射。
